## 一、包里有什么

| 路径 | 内容 |
|---|---|
| `desktop/src/main/` | Electron 主进程：窗口、认证、引擎路由、转换编排 |
| `desktop/src/preload/` | `contextBridge` 白名单（渲染层拿不到 fs / child_process / token） |
| `desktop/src/renderer/` | 登录页 + 主界面 + 转换矩阵（原生 HTML/CSS/JS，无框架） |
| `desktop/scripts/` | 启动器（不依赖 `npm i electron` 也能跑） |
| `desktop/tools/` | 桩服务端、自测、静态校验、预览构建 |
| `web/` | 网页版外壳（同一套 UI + 认证，浏览器直连） |
| `docs/` | 实施方案 v1.1 + 本说明 |

**不含**：引擎二进制（1.49 GB）、`node_modules`（152 MB）、`dist` 打包产物。这些由安装包提供，见 §2。

## 二、运行前提

1. **Node ≥ 22**（`package.json` 里 `engines` 同款）
2. **引擎目录** `desktop/engines/`：

```
engines/
├── ffmpeg/ffmpeg.exe                       (216.9 MB)
├── libreoffice/LibreOfficePortable/...     (888.7 MB)
├── poppler/Library/bin/                    (104.7 MB)
├── tessdata/                               (5.3 MB, chi_sim/eng/tha)
└── docengine/docengine.exe                 (273.7 MB, PDF→Word)
```

3. **Node 依赖**（离线环境从已有工程复制即可）：

```
pdf-lib · tesseract.js · tesseract.js-core · @tesseract.js-data · pdfjs-dist
```

```powershell
cd desktop

```

网页版：

```powershell
cd web
node server.mjs --server http://192.168.9.104 --port 5185
```

## 五、与引擎层的关系（重要）

**当前外壳用的是自研引擎适配**，不是 `format-converter-engine@0.2.2`。原因：

0.2.0 在受限环境（企业沙箱/EDR）里 `spawn EPERM`，四条转换全挂。B 侧改用「stderr 重定向到文件描述符」后跑通，于是先自研了一套，避免阻塞界面开发。

**0.2.2 已验证可用**（`FC_IO_MODE=file`）：

```
capabilities → missing: 无
png  → webp   206 ms
docx → pdf   7,565 ms
pdf  → png    230 ms
png  → pdf    232 ms
png  → txt    778 ms（OCR）
```

### 三处必须修正的配置（否则跑不起来）

| 项 | 交付说明 / CONTRACT 的写法 | 实际要求 |
|---|---|---|
| `FC_LIBREOFFICE_PATH` | `soffice.com`（正确） | 必须是 **`soffice.com`**；写 `.exe` 时 `capabilities()` 报 `OFFICE_ENGINE_BROKEN`（但 `convert()` 又能成功，状态自相矛盾） |
| `FC_TESSERACT_JS_DIR` | `path.join(appRoot,'node_modules','tesseract.js')` | **必须指向 `node_modules` 目录**。A 侧判断的是 `path.join(d,'tesseract.js','package.json')`，按文档写会得到 `OCR_MISSING`，且不说明原因 |
| `FC_IO_MODE` | 可选 | 受限环境建议**显式设 `file`**，不要依赖自动降级（自动降级会让首次任务白失败一次） |

## 六、请 A 组配合的四件事

1. **修正 `CONTRACT.md` §5.1** 的 `FC_TESSERACT_JS_DIR` 示例，以及 `FC_LIBREOFFICE_PATH` 用 `.com` 的理由（`.exe` 会导致能力探测失败）。
2. **`capabilities()` 与 `convert()` 判定不一致**：`.exe` 下探测报 BROKEN、转换却成功。建议探测与转换用同一套解析逻辑。
3. **`OCR_MISSING` 缺少细节**：应带上“试过哪些路径”，否则 B 侧只能靠猜。
4. **zip 能力没有对外入口说明**：B 侧需要“一个压缩包 → 多个产物”的返回结构约定（`files[]` 的长度、命名规则、失败成员怎么报）。
