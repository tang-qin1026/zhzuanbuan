## 一、需求理解

> 做一个和飞鼠格式同类的 Windows 桌面转换工具，但不自建账号体系——启动时用平台账号登录，其余全部本地完成。

| | 飞鼠格式 | 本产品 |
|---|---|---|
| 使用前提 | 下载即用 | 必须先通过平台认证 |
| 身份 | 无 | cloud-server 用户（nickname / role / 企业归属） |
| 联网 | 完全离线 | 仅认证与续期联网 |
| 数据 | 无 | 服务端 audit_logs 记录登录 |

## 二、范围

### 2.1 P0

1. Windows 10/11 x64 客户端（Electron）
2. 四步主流程：选择文件 → 识别格式 → 开始转换 → 保存结果

6. 诊断导出（日志、环境、引擎版本）

- 文件夹整体转 PDF
- 拖拽到窗口直接开始
- 深色/浅色跟随系统、中英双语

## 三、认证方案（按 2026-11-09 实测重写）

### 3.1 实测契约

| 项 | 实测值 | 验证方式 |
|---|---|---|
| 登录接口 | `POST {server}/api/auth/login`，body `{username, password}` | 真实账号，HTTP 200 / 739 ms |
| 响应外层 | `{code, message, data}`，`code = 0` 成功 | 实测 |
| `data` | `{accessToken, refreshToken, user}` | 实测 |
| 算法 | **HS512**（对称密钥在服务端，客户端无法验签） | 解码 JWT header |
| `iss` | **`cloud-server`** | 解码 payload |
| access | **7200 秒 / 120 分钟** | `exp − iat` |
| refresh | **1209600 秒 / 14 天** | `exp − iat` |
| 刷新 | `POST {server}/api/auth/refresh`，body `{refreshToken}` | 实测 200 |
| 刷新语义 | **轮换**：返回新 access + 新 refresh，旧 refresh 立即作废 | 复用旧 token → `40103` |
| token 版本 | payload 含 `uv`，账号禁用/改密后递增 | 源码 `AuthService.refresh()` |
| 会话保持 | 无 `Set-Cookie`，纯 Bearer | 响应头 |
| 登录限流 | 连续失败 4 次锁 15 分钟，message 含剩余次数 | 实测 |
| 传输 | nginx 1.27.5 + Spring Boot，**仅 HTTP** | 响应头 |

**结论**：客户端不直接访问门户，只访问 cloud-server 一个地址；门户由服务端内部代理。

### 3.2 设计

```
┌────────────┐  ① 账密          ┌──────────────────┐
│  桌面端     │ ───────────────▶ │ cloud-server     │──▶ 内部代理 ──▶ 门户
│            │ ◀─────────────── │ /api/auth/login  │
│            │  ② 双 token      └──────────────────┘
│            │  ③ DPAPI 加密落盘
│            │  ④ access 临近过期 → /api/auth/refresh（轮换）
│            │  ⑤ refresh 过期（14 天）或被吊销 → 回登录页
└────────────┘
```

- 客户端**不自造任何凭证**，长期状态由 refreshToken 轮换承担
- token 只存在于主进程内存与 DPAPI 加密文件，**永不进入渲染层**
- 离线可用：服务端不可达时保留本地凭证，恢复后自动续期

### 3.3 登录状态机

```
未登录 ──login()──▶ 已登录（内存持 token）
                      │
      access 剩余 <5min│ 静默 refresh
                      ▼
                  已续期 ──▶ 已登录
                      │
    refresh 返回 40103 / 40000 / HTTP 401
                      ▼
              会话失效 ──▶ 清本地 ──▶ 回登录页（onSessionLost 通知 UI）
                      │
    refresh 时网络不可达
                      ▼
              保持已登录（离线），下个周期再试
```

### 3.4 本地存储

```
%APPDATA%\<产品名>\auth.bin   ← DPAPI（CurrentUser）加密
{
  accessToken, refreshToken,
  username, nickname, role, enterpriseId, scope,
  mustChangePassword, enterpriseSuspended,
  quotaBytes, usedBytes,
  accessExp, refreshExp, savedAt
}
```

- **不做**机器指纹绑定、不做 HMAC、不自算有效期（到期时间从 token 的 `exp` 读）
- DPAPI 本身已提供用户级隔离：拷到别的 Windows 用户下解不开

### 3.5 客户端不解析、不校验 token

token 对客户端是不透明字符串，只做三件事：

1. 原样存储
2. 原样放进 `Authorization: Bearer <token>`
3. 从 payload 读 `exp` 决定是否提前续期（**只读，不校验签名**）

安全边界由服务端保证：每次请求验签、验吊销、验 `uv`、验账号状态。

> 对称密钥若下发到客户端，等于把签发权交给每个用户——那才是真漏洞。

### 3.6 错误处理（判断顺序，不是并列表）

```
1. HTTP 层失败（超时/连接拒绝）      → AUTH_UNAVAILABLE，提示"服务暂不可用"
2. 响应能解析出数字 code            → 以 code 为准（见下表）
3. 响应非 JSON 且 HTTP 401          → AUTH_SESSION_EXPIRED
4. 其它非 2xx                       → AUTH_UNAVAILABLE
```

| code | HTTP | 含义 | 客户端处理 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `40000` | 200 | 参数错误 | 登录时提示；**refresh 时按会话失效处理** |
| `40101` | 200 | 用户名或密码错误 | **原样展示 message**（含剩余次数） |
| `40101` + `已锁定` | 200 | 已锁定 15 分钟 | 展示 message，按钮禁用 15 分钟倒计时 |
| `40102` | 200 | 账号禁用 | 展示 message，禁止重试 |
| `40103` | 200 / 401 | 登录失效 | 尝试 refresh；refresh 也失效 → 回登录页 |
| `50000` | 200 | 系统繁忙 / 门户不可达 | 提示稍后重试 |

**三条硬规则**

```ts
// ① 判断"要重新登录"必须两个都看
const needLogin = (http, code) => http === 401 || code === 40103

// ② message 原样透传，不重写、不拼接
toast(msg)

// ③ 40000 在 refresh 场景等于会话失效，不是"内部错误"
```

### 3.7 登出

调 `POST /api/auth/logout`（吊销 jti）→ 清 `auth.bin`。网络失败也要清本地，不能因为服务端不可达就登不出去。

### 3.8 阻断态

| 字段 | 处理 |
|---|---|
| `mustChangePassword: true` | 进主界面但隐藏工作区，提示"需先在平台修改密码"（改密端点待定，见 §10） |
| `enterpriseSuspended: true` | 同上，红色提示，只保留"退出登录" |

### 3.9 用户名显示规则

服务端返回 `user.username = portal_<门户UUID>`（影子用户名），`user.nickname` 才是人看的名字。

> **界面任何位置显示用户名，一律用 `nickname`**，否则右上角会出现一串 UUID。
> 日志与诊断包同样不得打印 `accessToken` / `refreshToken`。

### 3.10 能力边界

| 能做 | 不能做 |
|---|---|
| 知道谁登录过、何时登录（audit_logs） | 统计真实转换次数（无上报） |
| 挡住"没账号的人" | 挡住"有账号但改客户端的人" |
| 服务端吊销单个 refresh token | 挡住"伪造一个完全离线的新客户端" |
| 账号禁用后失效（`disabled` + `uv`，**access 侧待验证**） | 一次性踢掉所有设备（无设备表） |
| 改密后旧凭证全部失效（`uv` 递增） | |
| 登录失败限流（4 次锁 15 分钟） | |

> 与 v1 相比性质变了：**从"防君子不防小人"升级为"服务端说了算"**，这是现成能力，不需要额外开发。

### 4.1 进程模型

```

```

强制：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。

### 4.2 模块

| 模块 | 职责 |
|---|---|
| `auth` | 登录、静默续期、登出、会话失效通知 |
| `probe` | 扩展名 + 魔数识别，可用目标格式 |
| `engine/*` | 四个引擎的薄封装，统一 `run(args, onProgress)` |
| `orchestrator` | 批量队列、并发、重试、取消、清理、产物校验 |

| `diagnose` | 日志/环境/引擎版本打包 |
| `ui` | 四步流程、批量、进度、错误 |

### 4.3 引擎硬约束（实测得出）

**LibreOffice 必须独立 profile**

```
soffice --headless --norestore --invisible --nodefault \
        -env:UserInstallation=file:///<jobScratch>/lo_profile \
        --convert-to pdf --outdir <out> <input>
```

| 配置 | 墙钟 | 结果 |
|---|---|---|
| 3 文件 × 独立 profile，并行 | 25.5 s | **3/3 成功** |
| 3 文件 × 共用默认 profile，并行 | 18.8 s | **2/3 成功，1 个产物缺失** |

共用 profile 时**上层只看到"转换完成"**，文件静默丢失。

要求：
1. profile 随 job 创建、随 job 删除
2. profile 不放 `%TEMP%`（批量堆积占 C 盘）
3. **校验产物数量 = 输入数量**，不能只看退出码

**并发上限**：8 核机器上 soffice 并发 2（3 个并行墙钟 17.4 s，相对串行 2.48× 加速），留余量给 ffmpeg。

**Poppler 必须 ASCII 路径**

中文路径会让 Poppler 找不到 `share/poppler`（报 `Couldn't open 'nameToUnicode' file`，路径显示为 GBK 转义）。同一份 PDF 放到 `C:\Temp\poppler_ascii` 则无报错。

```
引擎目录与 scratch 目录必须纯 ASCII：
  ✗ C:\Users\张三\AppData\Local\Temp
  ✓ C:\ProgramData\<产品>\engines\
  ✓ C:\ProgramData\<产品>\scratch\
兜底：启动时设置 POPPLER_DATADIR 指向 ASCII 路径
```

**资源护栏（PDF→图片最容易 OOM）**

```
单文档最多 500 页
单页像素上限 50,000,000
单批累计像素上限 100,000,000
单批页数上限 8（超预算自动串行分批）
单边尺寸上限 16384 px
单文件输出上限 512 MB
```

参考值：A4 @150 DPI = 1275×1650 ≈ 2.1 MPx/页，PNG ≈ 275 KB/页，3 页 1.19 s。

## 五、IPC 契约

```ts
auth: {
  login(username: string, password: string): Promise<AuthSession>  // 失败抛 {code, message}
  session(): Promise<AuthSession | null>    // 读本地，必要时静默续期
  status(): Promise<'authenticated' | 'need-login'>
  logout(): Promise<void>
  onSessionLost(cb: (p: { reason: string }) => void): () => void
}

interface AuthSession {
  displayName: string          // nickname
  username: string             // portal_<uuid>，仅内部使用
  role: string
  enterpriseId?: number
  scope?: string
  mustChangePassword: boolean
  enterpriseSuspended: boolean
  quotaBytes?: number
  usedBytes?: number
  expiresAt: number            // refresh 的 exp
  remainingDays: number
}
// 没有 accessToken、没有 refreshToken
```

转换相关（不变）：

```ts
probe(paths): Promise<FileInfo[]>
start(spec): Promise<{ jobId }>
cancel(jobId): Promise<void>   // resolve 时必须保证临时文件已清理
onProgress(cb): () => void      // 限流 ≤10 Hz，按 jobId + fileIndex 合并
onDone(cb): () => void
```

新增错误码：`OUTPUT_NOT_WRITABLE`（输出目录不可写）。

## 六、格式矩阵

| 源 | 可用目标 | 引擎 |
|---|---|---|
| png / jpg / webp / bmp / tiff | 互转 | FFmpeg |
| mp3 / wav / flac / aac / ogg / m4a | 互转 | FFmpeg |
| mp4 / mkv / avi / mov / webm | 互转、转 gif | FFmpeg |
| doc / docx / odt / rtf / txt | pdf / docx / odt / txt | LibreOffice |
| xls / xlsx / ods / csv | pdf / xlsx / ods / csv | LibreOffice |
| ppt / pptx / odp | pdf / pptx / odp | LibreOffice |
| **pdf** | **png / jpg / txt** | **Poppler** |
| 图片 / pdf | txt（OCR） | Tesseract |
| zip | 解压后批量 | 自研 |

**`pdf → docx` 移入 v2 待评估。** 理由：Poppler 只产出文本流与位图，LibreOffice 在这条链路帮不上忙；同类产品为此写了约 490 KB、三轮专项修复，作者自述"不保证全文可编辑、等价还原或改文后的分页"。工作量被 v1 严重低估。

单一数据源原则不变：新增格式只改 `formats.ts`。

| v1.0 的说法 | 实测 | 来源 |
|---|---|---|
